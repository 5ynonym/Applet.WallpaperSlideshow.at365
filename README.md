# Applet.WallpaperSlideshow.at365

WallpaperSlideshow.at365の壁紙描画をAppDock拡張へ移したWindows用Appletです。AppDock **v0.5.0以降**を使用してください。現在のバージョンは **v0.2.0** です。

- モニターごとに複数の画像ソースフォルダー、サブフォルダーの画像をまとめて抽選。1巡まで重複なし。
- Fill / Fit / Stretch / Center / Tile、タイル枚数、上下左右の余白に対応。
- ファイル監視、フォルダーの再作成・接続復旧、バックグラウンド描画を元の実装から引き継ぎ。
- AppDock内で次の壁紙・一時停止・再開・履歴サムネイル・画像を開く操作が可能。
- Applet専用のタスクトレイアイコン、トレイ項目、履歴ウィンドウは作りません。

## 設定と30秒後の開始

`publish.bat`で発行し、`deploy.bat "C:\Tools\AppDock"`でAppDock EXEの隣の`extensions/Applet.WallpaperSlideshow.at365`へ配置します。AppDockを起動し直すと一覧に表示されます。最初は無効なので、画像設定を保存してから有効化してください。

AppDockの「設定」→このAppletの「開始までの秒数」は既定**30秒**です。有効化、AppDock起動、Applet再起動から30秒後に**プロセス自体を起動**します。0で即時、最大86400秒。開始待ちの画面には開始予定時刻と「今すぐ開始」が表示されます。無効化・AppDock終了で予約を取り消し、待機中に秒数を保存するとそこから待ち直します。実行中の秒数変更は次回起動から適用します。

「モニターごとの画像設定」に次の**配列**を入力します。画面の左から右、同じX位置では上から下の順です。未設定の画面は黒になります。

```json
[
  {
    "Folders": ["C:/Wallpapers/Landscape", "C:/Wallpapers/Art"],
    "Mode": "Tile",
    "TileCount": 4,
    "PaddingLeft": 0,
    "PaddingRight": 0,
    "PaddingTop": 0,
    "PaddingBottom": 40
  },
  {
    "Folders": ["C:/Wallpapers/Portrait"],
    "Mode": "Fit"
  }
]
```

`Folders`はモニターごとに64件まで、絶対パスで指定します。重複フォルダーや親子フォルダーの重なる画像は、大文字小文字を区別せず重複除去します。旧設定の単一`Folder`も読み取れ、`Folders`と併記した場合は両方を使用します。存在しないフォルダーは監視の復旧対象になり、アクセスできるほかのフォルダーは使用できます。サブフォルダーのジャンクション・シンボリックリンクはたどりません。対応画像はJPEG / PNG / BMPです。

更新間隔、タイル間余白、履歴件数、サムネイルサイズはAppDockの設定フォームから変更します。設定はAppDockの`settings.json`内の`extensions["at365.wallpaper-slideshow"].settings`へ保存され、元のWallpaperSlideshowの設定は変更しません。不正な画像設定はログと操作パネルに表示し、前回の有効な設定を維持します。

手動停止は保存され、ロック解除で勝手に再開しません。ロック中・リモート接続中の停止は手動停止と独立しています。「次の壁紙」は停止中には切り替えません。停止・無効化・終了時に壁紙を消去する動作は元アプリを引き継ぎます。元アプリと同時に動かすと壁紙設定が競合するため、元アプリを終了して利用してください。本Appletからほかのプロセスを終了する処理はありません。

## 操作コマンド

AppDockの操作パネル、コマンドパレット、ピン留め、ショートカットから実行できます。

| コマンドID | 表示名 | 動作 |
| --- | --- | --- |
| `at365.wallpaper-slideshow.start` | 壁紙スライドショーを開始 | 手動停止を解除して再生。すでに再生中なら維持 |
| `at365.wallpaper-slideshow.stop` | 壁紙スライドショーを停止 | 定期更新を止め、現在の壁紙を消去。停止状態を保存 |
| `at365.wallpaper-slideshow.toggle` | 壁紙スライドショーの開始／停止を切り替え | 手動停止状態を反転して保存 |
| `at365.wallpaper-slideshow.next` | 次の壁紙に更新 | 更新間隔を待たず、次の画像で壁紙を再描画 |
| `at365.wallpaper-slideshow.history` | 最近使った壁紙を表示 | AppDock内の画像履歴を表示 |
| `at365.wallpaper-slideshow.data` | 壁紙のデータフォルダーを開く | 一時BMP・エラーログの保存先を開く |

開始・停止はAppletがロードされた後の再生操作です。Appletの有効化や30秒の遅延開始とは別に扱います。停止中・ロック中・リモート接続中は「次の壁紙に更新」で切り替えず、開始コマンドもロック・リモート接続による自動停止を解除しません。不正な画像設定を保存した場合も、開始・停止は前回の有効設定で操作できます。

既存の`pause`（一時停止）と`resume`（再開）は、既存ショートカットとの互換性のため維持しています。履歴の前後ページ、表示画像を開く、操作パネルへ戻るコマンドも利用できます。

## 履歴と負荷

AppDockの操作パネルから「最近使った壁紙」を開くと、モニター番号、サムネイル、画像サイズと「画像を開く」を表示します。4件ごとの前後ページ、「履歴を更新」「壁紙の操作に戻る」に対応。履歴はモニターごとに既定30件の**パスだけ**をメモリに保持し、Applet終了で消えます。0で履歴を無効化できます。

画像の走査・合成は同時に1件だけ。更新タイマーを重ねず、キャンセル済みの結果を適用しません。設定内容が同じ場合は描画をやり直さず、監視の保守は5秒間隔です。抽選のシャッフルは線形時間。タイル画像はサイズ情報から配置を決めて1枚ずつ読み込み・縮小・解放するため、全タイルの原寸画像を同時に保持しません。履歴は開いたページだけ、最大320×240pxで順次読み込み、ページ変更や操作画面へ戻る際に置換・解放します。サムネイルをディスクに保存せず、更新確認の常駐ポーリングもありません。

合成中は全モニターを覆うBMPと1画像のデコード領域が必要です。画像デコーダーは原寸データを一時的に使う場合があるため、メモリ使用量は画面解像度と画像サイズにも依存します。実機のCPU・メモリ負荷は`VERIFICATION.md`の測定範囲を参照してください。

一時BMPと`errors.log`は`%AppData%\at365\Applets\WallpaperSlideshow`に置きます。同じエラーは1分間抑制し、ログは約1MiBで世代交代します。元アプリのデータフォルダーとは分離しています。

## バージョン確認

manifestの`minimumHostVersion: "0.5.0"`で互換性を確認します。AppDockの「更新を確認」はGitHubの正式リリースを手動で問い合わせ、更新があればリリースページを開けます。問い合わせ先は`5ynonym/Applet.WallpaperSlideshow.at365`。リポジトリや正式リリースの公開前は「公開リリースが見つかりません」と表示されます。自動ダウンロード・自動更新は行いません。

## ビルド・検証

Windows、.NET 10 SDK、隣の`AppDock.at365`ソースが必要です。発行EXEはwin-x64の自己完結型で、利用先への.NETの別途インストールは不要です。

```powershell
dotnet build Applet.WallpaperSlideshow.at365.slnx -c Release
dotnet run --project Applet.WallpaperSlideshow.RegressionTests -c Release
.\publish.bat
.\deploy.bat "C:\Tools\AppDock"
```

引数なしの`deploy.bat`は、Git除外の`deploy.local.txt`先頭行、次にPowerShellスクリプトの既定の兄弟AppDockの`publish`を使用します。`scripts/publish.ps1`へ任意の出力先を渡せます。配置スクリプトは先に発行されたEXEとmanifestだけをコピーし、実行中アプリを強制終了しません。

回帰テストは複数フォルダーの重複排除、抽選、タイル描画、負のモニター座標、キャンセル、画像の解放、フォルダー監視の復旧、ログを確認します。`scripts/test-protocol.cjs`と`scripts/test-ui.cjs`はテスト専用エンジンを使い、実際の壁紙や画像フォルダーに触れずAppDockとの通信と画面を検証します。
